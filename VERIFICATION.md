## Windows progress-file lock fix

- Fixed the reported `[WinError 5]` when replacing `progress.json.tmp` with `progress.json`. Windows can deny an atomic replacement while another reader or scanner has the destination open. Previously that momentary error aborted the worker, even after model inference finished.
- JSON writes now use a unique temporary file per writer and retry Windows access/sharing/lock errors (5, 32, 33) with bounded backoff totaling at most 1.81 seconds. Replacement stays atomic: readers never see a truncated JSON file. Permanent failures still propagate, preserving the previous JSON; unrelated errors are not retried. Temporary files are cleaned up when possible.
- **83 tests passed** in both the Python 3.12/PyTorch 2.8 and Python 3.11/PyTorch 2.2.2 Windows environments. Seven added checks include a real Windows open-file lock that first rejects replacement and then releases it, simulated transient errors, bounded permanent failure, unrelated disk errors, and concurrent writers with independent temporary files.
